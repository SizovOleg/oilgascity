## Context

Wagtail 7.3rc1 headless (SQLite) отдаёт контент через `/wt-api/v2/pages/`, React SPA собирается
в деплое (`scripts/build-frontend.sh`). Макет v2 содержит много структурированного контента
(10 результатов с цифрами, графики, таблица методов, доклады, архивы, глоссарий), который
владелец хочет править сам.

## Goals / Non-Goals

**Goals:** реализовать макет v2 на React без анимаций, скрывающих текст; весь новый контент
редактируется в админке; старые адреса не ломаются; сайт читается на 375 px.

**Non-Goals:** предпросмотр черновиков, англоязычная версия сайта, серверный рендеринг,
библиотека литературы (данных пока нет), сам геопортал (отдельное изменение `geoportal-prototype`).

## Decisions

1. **Одна модель `ReportPage` с StreamField** для «Результатов 2025», «Результатов 2026» и
   «Материалов» (поле `kind`). Альтернатива: отдельные модели с InlinePanel под каждый тип
   данных; отвергнута, так как блоки повторяются (рисунок, график, цифры) и разделов немного.
2. **Набор блоков в `home/blocks.py`**: section (якорь и заголовок для оглавления), paragraph,
   stats, result, figure, bar_chart, pair_chart, methods_table, plates, status, talks, archives,
   glossary, photo_counts, layer_cards, embed (вставка данных других страниц: публикации,
   экспедиции, коллектив, фототека). Картинки отдаются блоком с адресами копий
   (`thumbnail`, `large`, `original`), RichText отдаётся развёрнутым HTML.
3. **Нумерация рисунков** считается на фронтенде одним проходом по блокам страницы до рендера,
   поэтому «Рис. N» стабильны и совпадают со ссылками `#fig-N`.
4. **Фототека** собирается на фронтенде из галерей городов, экспедиций и новостей
   (новые поля галерей: `theme`, `shot_date`, `author`); счётчики архива задаются блоком.
5. **Стили**: CSS макета переносится как есть в `src/styles/site.css` (без Tailwind), шрифты
   Onest и Spectral из Google Fonts. Пустые поля не показываются, заглушки макета на живой
   сайт не попадают.
6. **Адреса**: `/`, `/cities/:slug`, `/results/:year`, `/materials`, `/news`, `/news/:id`,
   `/expeditions/:id`, `/geoportal`; старые перенаправляются. `FrontendUrlMixin` ведёт
   «Посмотреть на сайте» в админке на новые адреса.

## Risks / Trade-offs

- [Миграция боевой базы] → копия SQLite перед деплоем, миграции только добавляют поля и модель.
- [Контент заводится скриптом, а не руками] → загрузчик идемпотентный, проверяется на копии
  боевой базы до запуска на проде.
- [Сайт без SSR, поисковики видят пустую страницу до выполнения JS] → текст больше не прячется
  за анимацией; заголовки страниц ставятся через document.title; SSR вне рамок изменения.
- [Длинная страница «Материалы» на телефоне] → оглавление и якоря; разбивка на подстраницы позже.

## Migration Plan

1. Бэкенд (модели, миграции, API) выкатывается первым, старый фронтенд с ним совместим.
2. На проде: копия базы, загрузчик контента, проверка API.
3. Фронтенд выкатывается вторым коммитом, деплой собирает его сам.
4. Откат: `git revert` фронтенда пересобирает старую версию; база возвращается из копии.
