## Context

Мотивация: proposal.md, раздел Why. Требования: specs/media-storage/spec.md.

Сейчас Wagtail пишет загрузки в `backend/media/` (`FileSystemStorage`), nginx отдаёт их
через `location /oilgascity-media/ { alias ...; }`, API возвращает относительные адреса
`/oilgascity-media/...`. Прод: Django 6.0.2, Wagtail 7.3rc1, SQLite; настройки прода в
`settings/production.py`, секреты в `/etc/oilgascity-wagtail.env` (systemd drop-in,
`scripts/deploy.sh` их тоже подключает). nginx общий с другими сайтами. На сервере есть
rclone и монтирование закрытого бакета `EOdata` (кластер аккаунта f003), его ключ видит
только этот бакет.

Проверено 2026-11-19 (Django 6.0.2, Wagtail 7.3rc1, django-storages 1.14.6, boto3 1.44.6,
moto вместо B2): загрузка оригинала и рендера в бакет, рендер переиспользуется,
одинаковые имена не затирают друг друга при `file_overwrite=False`, адреса через
`custom_domain` с путём получаются `https://oilgascity.ru/oilgascity-media/...`, документ
отдаётся через `/documents/<id>/<имя>` при `WAGTAILDOCS_SERVE_METHOD="serve_view"`.

## Goals / Non-Goals

**Goals:**
- Переключение хранилища одной переменной, откат без изменения кода.
- Ни один адрес медиа на сайте и в API не меняет домен и префикс.
- Шаблон, который переносится на reliefwestsib правкой переменных окружения.

**Non-Goals:**
- Закрытые (приватные) документы: сейчас документов 0 и закрытых коллекций нет; см. Risks.
- Сторонний CDN, обработка изображений на стороне хранилища.
- Удаление локальной папки `media/` (решение владельца после периода наблюдения).

## Decisions

1. **django-storages `S3Storage` по S3 API B2.** Сопровождаемый пакет, штатно
   поддерживается Wagtail. Альтернативы: монтирование rclone как MEDIA_ROOT (без кода, но
   падение FUSE ломает все картинки; владелец выбрал S3 API), нативный B2 API
   (`django-b2`, малоизвестный пакет), Cloudflare R2 (другой поставщик, новый аккаунт).
   1.14.6 официально заявляет Django до 5.1; совместимость с 6.0 проверена эмпирически
   (см. Context), версии фиксируются в requirements.

2. **Отдельный публичный бакет на сайт и ключ только к нему.** Публичность нужна, чтобы
   nginx брал файлы без подписи запросов. Ключ приложения ограничен одним бакетом
   (Read and Write): компрометация сайта не открывает `EOdata` и бакеты других сайтов.
   Альтернатива: один бакет с префиксами на сайты, ключи по префиксу; отвергнуто ради
   простоты и раздельного учёта.

3. **Обход проверки checksum в boto3.** B2 отвергает заголовки
   `x-amz-sdk-checksum-algorithm`, которые boto3 ≥ 1.35.99 шлёт по умолчанию
   (django-storages #1498). Опция `client_config` (не устарела, #1482):
   `Config(signature_version="s3v4", s3={"addressing_style": "virtual"},
   request_checksum_calculation="when_required", response_checksum_validation="when_required")`.
   `client_config` заменяет стандартный конфиг целиком, поэтому стиль адресации и подпись
   заданы в нём явно. На реальном B2 проверяется первой операцией после создания бакета.

4. **Адреса через `custom_domain = "<домен>/oilgascity-media"`, без подписи
   (`querystring_auth=False`).** Адрес получается `https://oilgascity.ru/oilgascity-media/<ключ>`,
   ключи в бакете совпадают с путями в `media/` (`original_images/...`, `images/...`,
   `documents/...`), поэтому ссылки до и после переноса одинаковы. Альтернатива: прямые
   адреса B2 (`f003.backblazeb2.com/file/...`) меняют домен и тратят исходящий трафик B2.

5. **nginx: `location /oilgascity-media/` проксирует на публичный адрес бакета с
   `proxy_cache`.** Зона кэша на диске сервера (до 5 ГБ, неактивные записи 60 дней),
   200 кэшируются на 30 дней, 404 на минуту, при ошибке хранилища отдаётся устаревшая
   копия (`proxy_cache_use_stale`), `proxy_cache_lock` против лавины запросов. Служебные
   заголовки `x-bz-*` скрываются, добавляется `X-Cache-Status` для проверки. Файлы в
   Wagtail не перезаписываются (уникальные имена), поэтому долгий кэш безопасен.
   Конфиг готовится заранее, включается только при переключении.

6. **Документы через `serve_view`.** Wagtail проверяет ограничения коллекции и отдаёт
   файл потоком через Django; `/documents/` уже проксируется nginx. Альтернатива
   `redirect` выдала бы посетителю прямую ссылку в бакет и обошла бы проверку доступа.

7. **Флаг `MEDIA_STORAGE=s3`.** Без него `FileSystemStorage`, как сейчас. С флагом
   обязательны `MEDIA_S3_BUCKET`, `MEDIA_S3_ENDPOINT_URL`, `MEDIA_S3_REGION`,
   `MEDIA_S3_ACCESS_KEY_ID`, `MEDIA_S3_SECRET_ACCESS_KEY`; при пропуске приложение не
   стартует с именем недостающей переменной (fail closed). Необязательные:
   `MEDIA_S3_LOCATION` (префикс в бакете, по умолчанию пусто), `MEDIA_PUBLIC_DOMAIN`
   (по умолчанию `oilgascity.ru/oilgascity-media`). Сборка настроек вынесена в
   функцию, которую можно проверить юнит-тестом без сети.

8. **Перенос rclone с ключом из окружения.** `scripts/migrate-media-to-b2.sh` подключает
   `/etc/oilgascity-wagtail.env` и вызывает rclone с удалённым хранилищем «на лету»
   (`:s3:` и переменные `RCLONE_S3_*`), ключ не пишется ни в конфиг, ни в командную
   строку. `rclone copy` без удаления, затем `rclone check --one-way` (размер и хэш) и
   сверка числа файлов. Повторный запуск безопасен: дозаливает только недостающее.

## Risks / Trade-offs

- [B2 отвергнет запросы boto3 несмотря на `when_required`] → проверка записи и чтения
  тестовым файлом до переключения; запасной вариант: зафиксировать boto3 1.35.x.
- [Публичный бакет: файл документа доступен по прямому адресу B2, имя угадываемо] →
  сейчас так же доступен через nginx по `/oilgascity-media/documents/`; закрытых
  документов нет. Если понадобятся: отдельное закрытое хранилище для документов.
- [Хранилище недоступно] → nginx отдаёт из кэша уже запрошенные файлы; новые загрузки в
  админке падают с ошибкой (видна в журнале); откат флагом.
- [Загрузки, сделанные после переключения, при откате отсутствуют локально] → перед
  откатом скопировать бакет обратно: `rclone copy` в обратную сторону тем же скриптом
  с ключом `--reverse`.
- [django-storages 1.14.6 не заявляет Django 6] → версии зафиксированы, интеграционные
  тесты с moto в наборе тестов проекта; обновление Django проверять этими тестами.
- [Расходы B2] → 97 МБ сейчас, исходящий трафик в основном гасит кэш nginx.

## Migration Plan

1. Владелец создаёт публичный бакет и ключ приложения только к нему, вписывает
   `MEDIA_S3_*` в `/etc/oilgascity-wagtail.env` (флаг пока не ставит).
2. Деплой кода (push в main с согласия владельца): без флага поведение не меняется.
3. Проверка доступа: запись, чтение и удаление тестового объекта через Django shell.
4. `scripts/migrate-media-to-b2.sh`: копия 66 файлов, `rclone check`, сверка числа.
5. `MEDIA_STORAGE=s3` в env, перезапуск: новые загрузки и рендеры идут в бакет. Сразу
   повторный запуск скрипта переноса досылает файлы, легшие на диск между шагами 4 и 5.
   Порядок важен: если переключить nginx раньше флага, рендеры, созданные в этом окне,
   окажутся только на диске, а nginx закэширует для них 404.
6. nginx: `scripts/nginx/install-media-proxy.sh` (бэкап конфига, сниппет с кэшем,
   `nginx -t`, reload). С этого момента сайт читает файлы из бакета (адреса те же).
   Проверка: картинки на сайте, второй запрос `X-Cache-Status: HIT`, тестовая загрузка
   в админке появилась в бакете, а не на диске.
7. `scripts/backup.sh` сам переходит на бэкап только базы, прочитав флаг из env;
   внеочередной прогон для проверки.

Проверено до включения (2026-11-19, на сервере в песочнице, живой nginx не тронут):
установщик nginx ставит и снимает сниппет, `nginx -t` проходит; временный nginx через
этот сниппет дошёл до B2 (закрытый `EOdata` ответил 401, ответ не закэширован, заголовки
`x-amz-*` скрыты), ключ с кириллицей передан в исходной кодировке; скрипт переноса
скопировал и сверил 66 файлов, поймал пропавший файл, отработал `--reverse`.

Откат: `scripts/migrate-media-to-b2.sh --reverse` (загрузки после переключения на диск),
убрать `MEDIA_STORAGE`, перезапустить сервис, `scripts/nginx/install-media-proxy.sh
--uninstall` (возвращает `alias` на диск, `nginx -t`, reload).

## Open Questions

- Точный endpoint и регион бакета (ожидается `s3.eu-central-003.backblazeb2.com`,
  `eu-central-003` по кластеру f003): владелец видит их в консоли при создании бакета.
- Имя бакета: глобально уникально в B2, выбирает владелец (например `oilgascity-media-<суффикс>`).
