## Purpose

Определяет, где хранятся загрузки сайта (изображения, их рендеры, документы), по каким
адресам их получают посетители и как внешнее хранилище включается и откатывается.

## ADDED Requirements

### Requirement: Загрузки хранятся во внешнем объектном хранилище
При включённом внешнем хранилище система SHALL сохранять каждый новый загруженный файл
(оригинал изображения, рендер, документ) в объектное хранилище, а не на диск сервера.

#### Scenario: Загрузка изображения в админке
- **WHEN** редактор загружает изображение в админке при включённом внешнем хранилище
- **THEN** оригинал появляется в бакете, а на диске сервера в папке медиа новый файл не появляется

#### Scenario: Рендер для API
- **WHEN** API впервые запрашивает уменьшенную копию изображения
- **THEN** рендер создаётся и сохраняется в бакете, повторный запрос его не пересоздаёт

### Requirement: Адреса медиа не меняются при переключении
Система SHALL отдавать файлы посетителям по адресам вида
`https://oilgascity.ru/oilgascity-media/<путь>`, одинаковым для локального и внешнего
хранилища; ссылки с адресом самого бакета MUST NOT попадать в страницы и ответы API.

#### Scenario: Картинка после переключения
- **WHEN** посетитель открывает страницу, где есть изображение, загруженное до переключения
- **THEN** изображение загружается по адресу на домене `oilgascity.ru` с префиксом `/oilgascity-media/`

#### Scenario: Адрес в ответе API
- **WHEN** клиент получает страницу через `/wt-api/v2/` при включённом внешнем хранилище
- **THEN** поля изображений содержат адреса на `oilgascity.ru/oilgascity-media/`, без домена хранилища

### Requirement: Файлы раздаются с кэшем на сервере
Сервер SHALL кэшировать файлы, полученные из хранилища, и отдавать повторные запросы
из кэша без обращения к хранилищу, пока запись в кэше свежая.

#### Scenario: Повторный запрос картинки
- **WHEN** один и тот же файл запрашивают дважды подряд
- **THEN** второй ответ отдаётся из кэша сервера

### Requirement: Документы отдаются через сайт с проверкой доступа
Документы SHALL отдаваться по адресам `/documents/<id>/<имя>` через приложение, которое
проверяет ограничения доступа коллекции; прямая ссылка на файл документа в хранилище
MUST NOT выдаваться посетителю.

#### Scenario: Публичный документ
- **WHEN** посетитель открывает ссылку на PDF публикации
- **THEN** файл скачивается по адресу `/documents/...` на `oilgascity.ru`

#### Scenario: Документ из закрытой коллекции
- **WHEN** анонимный посетитель открывает документ из коллекции с ограничением доступа
- **THEN** приложение не отдаёт файл без выполнения условия доступа

### Requirement: Включение по флагу и откат
Внешнее хранилище SHALL включаться только явным флагом в окружении сервера; без флага
система MUST хранить файлы на локальном диске. Наличие ключей доступа без флага MUST NOT
менять поведение.

#### Scenario: Ключи заданы, флага нет
- **WHEN** в окружении есть ключи хранилища, но флаг не установлен
- **THEN** новые загрузки сохраняются на локальный диск, как до изменения

#### Scenario: Флаг включён без ключей
- **WHEN** флаг установлен, а обязательные параметры хранилища не заданы
- **THEN** приложение не запускается и сообщает, какого параметра не хватает

#### Scenario: Откат
- **WHEN** флаг убирают и перезапускают сервис
- **THEN** сайт снова отдаёт файлы с локального диска

### Requirement: Перенос существующих файлов без потерь
Перенос SHALL скопировать в хранилище все файлы локальной папки медиа с сохранением
путей и MUST сверить число и размер файлов до и после; локальные файлы MUST остаться
на месте как резерв.

#### Scenario: Сверка после переноса
- **WHEN** перенос завершён
- **THEN** число файлов в бакете равно числу файлов в локальной папке, расхождения выводятся списком
